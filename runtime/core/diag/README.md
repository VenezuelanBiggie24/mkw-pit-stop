# runtime/core/diag

Diagnostics: flight recorder, counters and profiling, RenderDoc, game phases and the census of SDK calls.

| File | What it is |
|---|---|
| `flight.c`, `flight.h`, `perf.c`, `prof*`, `perfmon.*`, `rdoc.c` | Diagnostics: flight recorder, counters, profiling, RenderDoc |

The sampling profiler (`MKW_PROFILE`) is `prof_win.c` on Windows and `prof_posix.c` on Linux and the PS5 (a sampler thread signals each runtime thread, `platform/sigsample.c`; the log names lifted functions as `main+0x...` and host functions from the executable's symbols, or the PS5 title's `mkw.sym`).
| `hangwatch.c`, `hangwatch.h` | `MKW_HANG_WATCH=<s>` (default 10 on the PS5): each runtime thread's last checkpoint (`hang_mark`) and the owners of the queue, sparse and upload locks, and every runtime thread's stack with names (`MKW_HANG_STACKS=0` turns that off; read on each thread through `platform/sigsample.c`), logged once the game stops presenting for that long |
| `seqwatch.c` | `MKW_SEQ_WATCH=1`: entries and exits of the game's phases (`seq: enter TitleMenuMain frame N`) through the function-entry hook of the translated code; the `seq` command of the control channel; `MKW_SEQ_HOLD` holds the button script while a phase lasts; `MKW_SEQ_UNTIL`/`MKW_SEQ_EXIT`: goes off at a phase and exits N s later (`tools/run/race.sh`) |
| `pgo.c` | Profile-guided optimization: writes the counters of a build with instrumented game code (`tools/build/build.py --pgo-gen DIR`) at `MKW_PGO_AT=<frame>[,<frame>...]` (each file one stretch of the run, `DIR/mkw-<pid>-f<frame>.profraw`, counters reset after it) and at clean `plat_exit` (`-exit.profraw`), since runs end by `_exit` and the profile runtime writes only at `atexit`. What is counted while the function-entry hook is on is dropped. Linux and Windows: the PS5 SDK has no profile runtime, so the PS5 build uses a PC profile (`tools/ps5/build_game.py --pgo-use`, [docs/ps5/ps5.md](../../../docs/ps5/ps5.md#profile-guided-build)) |
| `bench.c`, `bench.h` | `MKW_BENCH=tt\|gp\|ko` (Hacks tab for tt and gp, `mkw.ini` for ko; `tools/ps5/bench.py` runs it on the PS5): a time trial, a Grand Prix or a Knockout Tour (ko, the memory test: legs and rallies one after another for `MKW_BENCH_MAX`, up to 4 h, or `MKW_BENCH_RALLIES` rallies, split into segments at each rally's opening) the same on every run (`MKW_QUICK_RACE=<mode>`, `MKW_SEED=1`, `MKW_SKIP_MOVIES=1` unless set, `core/base/cfg.c`), driven by Smart Steering, Auto-Accelerate and Auto-Use Item (`Play/account.sav`) plus bench-only virtual overrides (`bench_patch_hosts`) that hand player 1 to the game's CPU driver (`Almighty`, rivals `Easy3`), prevent player 1 knockout in ko (`MKW_BENCH_NO_DROPOUT`, default on in ko, never outside bench) and log each leg's place (`legs=`, `best_place=`, `last_place=`, `dropouts_prevented=`). From the first race to the finish (`MKW_BENCH_MAX=<s>` if none), the frame times, with save writes and movies as marks that split it into segments; then the log's `bench:` lines (average, 1 % and 0.1 % lows, worst frame, frames over 33.3 and 50 ms, per segment too), the memory report (`bench_mem.c`) and exit |
| `bench_mem.c`, `bench_mem.h` | The benchmark's memory report: a `bench-mem` thread samples once a second from the window's start (PS5: free direct memory over all areas and the largest, backed guest memory, free flexible memory, page-table units; Linux and Windows: process resident and private memory, machine available memory; everywhere: driver heap usage, VMA, live and released textures, sparse, shadows, governor passes, out-of-memory reliefs, deferred staging uploads), logs `bench: mem t=...` every 30 s, and reports start, end, worst and trend per minute for the window and each segment, with `bench: memresult` for `bench.py` (`tools/run/bench_mem.py` reads the periodic lines of a run that never reached the report) |
| `bench.c`, `bench.h` | `MKW_BENCH=tt\|gp\|ko` (Hacks tab for tt and gp, `mkw.ini` for ko; `tools/ps5/bench.py` runs it on the PS5): a time trial, a Grand Prix or a Knockout Tour (ko, the memory test: legs and rallies one after another for `MKW_BENCH_MAX`, up to 4 h, or `MKW_BENCH_RALLIES` rallies, split into segments at each rally's opening) the same on every run (`MKW_QUICK_RACE=<mode>`, `MKW_SEED=1`, `MKW_SKIP_MOVIES=1` unless set, `core/base/cfg.c`), driven by the game's Smart Steering and Auto-Accelerate (turned on in `Play/account.sav` when the game opens it). From the first race to the time trial's save at the finish or the cup's ending movie (`MKW_BENCH_MAX=<s>` if none), the frame times, with save writes and movies as marks that split it into segments; then the log's `bench:` lines (average, 1 % and 0.1 % lows, worst frame, frames over 33.3 and 50 ms, per segment too), the memory report (`bench_mem.c`) and exit |
| `bench_mem.c`, `bench_mem.h` | The benchmark's memory report: a `bench-mem` thread samples once a second from the window's start (PS5: free direct memory over all areas and the largest, backed guest memory, free flexible memory, page-table units, the title heap's mapped direct memory; Linux and Windows: process resident and private memory, machine available memory; everywhere: driver heap usage, VMA, live and released textures, sparse, shadows, governor passes, out-of-memory reliefs, deferred staging uploads), logs `bench: mem t=...` every 30 s, and reports start, end, worst and trend per minute for the window and each segment, with `bench: memresult` for `bench.py` (`tools/run/bench_mem.py` reads the periodic lines of a run that never reached the report). In a bench run `MKW_POOL_LOG` (`gfx/vk/mem/vk_memory.c`) also logs each NVN pool of 1 MiB or more as the game creates and finalizes it (frame, kind, size, flags, age, guest memory backed and released) |
| `impcensus.c` | `MKW_IMPORT_CENSUS=<file>`: which SDK functions the game code calls during the run, how many times and from which frame, through the same entry hook as `seqwatch.c`; read by `tools/analisis/runtime/sdk_gaps.py --census` |
